# JustEnoughGuide 2.1.74 — First-Join Guide and Recipe Completion Safety

**Release candidate only. Not published.** Public v2.1.73 remains available until this candidate passes its exact-head build, bundled Pinyin startup, offline-profile and native guide checks.

## Included repairs

- **Correct first-join guide ownership** ([PR #23](https://github.com/wickidcow/SF_JustEnoughGuide/pull/23)). Upstream JustEnoughGuide previously intercepted SlimefunGuideListener's right-click callback, leaving its first-join giveaway enabled and potentially awarding two guides. Intercept the original Slimefun **PlayerJoinEvent** listener instead. Restore it to the same handler list on JEG unload/reload; upstream's fix did not update that restoration target.
- **Conserve partial recipe-completion withdrawals** ([PR #22](https://github.com/wickidcow/SF_JustEnoughGuide/pull/22)). The ingredient source returns the number of items actually withdrawn, not an incorrect zero when several sources partially fulfill the requested amount.
- Preserve bundled Pinyin search dictionaries, existing English menu/search/bookmark features, Recovery Center, `/sf tick top`, and guide renderer compatibility.

## Data, dependency, and platform contract

- No player bookmark/history migration or reset; no item, recipe or persistent-data IDs are changed.
- No new GuizhanLibPlugin dependency, Bedrock/Geyser feature or NMS fake-player behavior.
- Java 21 bytecode produced with JDK 25. Test with Slimefun Legacy on Paper/Purpur 1.21.11 and 26.2/26.3, plus the existing Leaf/Folia compatibility gates.
- Test the new-player join on a fresh profile, right-click the original guide, disable/reload JEG, and verify no duplicate books and correct Slimefun event handler restoration.
- Keep releases for earlier versions immutable and preserve the canonical distributable filename `SF_JustEnoughGuide2.1.74.jar`.
